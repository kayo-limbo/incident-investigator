# Bundle 失败诊断与候选保留

日期：2026-11-05。范围：新证据包协议的诊断字段与离线回归，不修改模型提示、动作 Schema、工具权限、校验规则或预算，不增加自动纠错。

## 问题与证据边界

[首轮对照](../experiments/bundle-comparison.md) 的假设策略失败包含4次结论引用未关联、3次引用非法、3次动作Schema失败。旧报告只保存固定原因码和已接纳状态，没有被拒绝候选或Schema路径。因此不能从旧报告还原具体错误字段，本次测试采用这些错误类型的最小合成样本，不称为原模型响应重放。

## 新报告字段

| 字段 | 内容及边界 |
| --- | --- |
| diagnostic | 复用原有阶段、分类、固定原因码、模型轮次与错误类型；覆盖模型请求/解析、数据源及动作校验失败 |
| schema_issues | 最多24项，每项为错误类型与最多16段字段路径；路径仅保留动作Schema已声明字段名、tool/finish分支名与有界数组下标，未知名称替换为 &lt;unknown&gt; |
| schema_issues_truncated | 错误数量或路径深度超限时标记，不能据截断结果声称只有这些错误 |
| rejected_candidate | status为schema_invalid/stored/too_large；只有通过动作Schema的候选可保存action，UTF-8 JSON最多16KiB，过大整份省略而非截断成不完整动作 |
| rejected_finding | 已有字段，现仅在失败finish候选可保存时填入，与被接受的finding明确分开 |

Schema不合法时不保存原对象、未知字段名、原值、错误消息或ctx。Schema合法的候选仍可能包含模型文本与观测引用，不是自动脱敏结果；报告继续作为本地私有实验产物保存。16KiB约束针对候选action，报告中的已有证据、已接纳假设及兼容的rejected_finding不计入该上限。

引用/关联失败时，假设账本、已接纳结论与查询次数不因保存候选而变化。重复查询仍停止，并保存其被拒绝候选，不把这一主动停止规则标成Schema错误。token/时间预算优先于动作校验时不伪造被拒绝候选。解析失败尚未得到合法动作，也不保存原始供应商文本。

诊断字段只进入终止报告，不进入BundleContext或后续模型反馈。旧报告缺省为空列表/None，旧模型成绩不回填、不改写；旧窗口协议与Worker检查点没有变化。

## 验证

新增9项离线测试，与原14项bundle测试合计23项通过：

- Schema字段路径、未知名称隐藏、错误项上限、无效原值不落报告。
- 跨快照引用、未关联结论、候选深拷贝、状态不提交、独立修正夹具能通过。
- 超大候选整体省略，重复动作附带假设更新仍拒绝。
- MockTransport解析失败保留真实适配器用量与原因码，不伪造候选。
- token先停止、诊断不进入上下文、旧报告默认值与数据源失败。

本地只读加载上轮30份固定/模型报告，使用当前类型与score逐份核对评分和用量，结果一致，文件hash未变；没有调用模型。此检查不等于用新代码重跑旧冻结协议：旧计划指纹与当前代码不同，正式运行入口仍拒绝继续旧计划。若要完整重现旧命令，应使用该轮归档源版本；新的模型实验必须新建计划。
