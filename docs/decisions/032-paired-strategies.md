# 双窗口三策略入口与强规则基线

2026-11-07：实现paired-bundle-v2的固定规则、普通ReAct、显式假设三种执行入口。复用已有LangGraph串行图、调用账本、时间/token预算及失败候选诊断；没有新增框架依赖，未接入Worker持久化恢复。普通/假设策略本轮仅用脚本替身验证，没有真实模型效果结果。

## 输入与报告

三策略都只读取同一快照的初始告警，通过reference/incident × trace/runtime四个只读工具取得证据。初始告警计一次工具调用，默认上限6，每个组合最多一次。模型只看安全观测投影，不读实验清单、注入配置或场景名称；引用包含snapshot_id/window/source/field。v1不冒充v2，返回source_error。

报告区分stage（no_anomaly/downstream/pre_send/mixed/unknown）与code（无异常、下游变化、容量变化、入口变化、竞争变化、证据不足）。因此缺少运行观测时仍能定位发送前耗时，但可以拒绝解释变化原因。

规则和两种模型提示公开相同判别条件：

- 每个耗时字段分别排序，P95取ceil(0.95*n)，至少5个有效样本；引用实际分位位置，不用最大值代替。
- 参考正常要求库存<150ms、发送前<50ms、订单<150ms且无失败；参考已异常时保守拒绝新增变化解释。
- 库存P95≥250ms为下游慢，发送前≥150ms或PoolTimeout为发送前异常；两者同时出现为mixed。
- 库存相比参考增加≥100ms支持下游变化。容量/入口解释还要求发送前阶段、库存<150ms、订单增加≥100ms、超时配置不变；分别比较池容量下降且速率比0.9—1.1，或池容量不变且速率比≥1.5。
- 入口速率只用before→send_end；多个候选因素同时变化保留竞争解释，不声称唯一因果。池下降本身不证明容量是根因。

固定策略顺序读取四个工具，含告警共5次。Agent可动态选择，但只有四种整窗查询，当前尚不足以证明主动调查收益。首次提出两个竞争假设是提示要求，未增加硬性双假设校验。

确定性结论需引用两个已查询的Trace；容量/入口/竞争解释还需两个运行观测。**这是来源与引用校验，不是语义验证器**：引用合法但code错误仍可能通过。最终不能由该规则同时充当唯一质量评委，仍需注入真值、独立业务观测与逐主张审查。

## 使用与本轮验证

默认固定规则完全离线，输出使用独占创建，不覆盖旧报告：

```powershell
python -m backend.investigation.paired_cli SNAPSHOT_SHA256 --store .snapshots/paired-20261107-cutoff-v2/snapshots --output .snapshots/new-report.private.json
python -m evals.replay_paired_fixed .snapshots/paired-20261107-cutoff-v2 --output .snapshots/new-replay.private.json
python -m unittest discover -s tests -p 'test_paired_investigation.py' -v
```

CLI显式选择`--strategy agent`或`hypotheses`才读取模型配置并发送证据，使用已有ModelConfig环境变量。默认120秒、40000累计token停止阈值；响应后计量可能超额，非费用硬上限。取消保存部分报告。配置或基础设施异常可能留下空输出文件，重试需使用新路径。

本轮只读回放既有v2容量/入口各两份开发快照：完整证据4份输出对应变化解释；trace_only四份保留pre_send阶段并拒答原因；runtime_only四份为unknown并拒答。每份调用5个工具，模型调用0。报告保存在忽略目录`.snapshots/paired-fixed-replay.private.json`，附输入manifest SHA256与调查代码指纹。原采集结果未改写；本次回放不替代原冻结采集audit，也不是12份独立样本或泛化准确率。
