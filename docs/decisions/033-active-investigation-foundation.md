# 主动调查的实验基础与参数计划

2026-11-09。目标是形成可验证的主动调查技术亮点。本轮只完成实验基础，不急于模型跑分，也不增加多Agent角色。

## 已实现的计划边界

`evals/paired_plan.py`验证显式参数：场景、开发/保留集标签、窗口时长、重复次数及两窗口的库存延迟/池容量/发送速率。拒绝额外字段、非整数控制量、越界负载及与场景机制不符的变化。上限仍为每窗口1000请求、100在途、5秒单请求超时和10秒排空；计时与业务验收阈值没有放宽。

`collect_paired_windows --plan`将规范化输入写入独占运行目录，归档源码及其SHA256，采集与audit均使用该计划，而不是运行时重新查默认参数。原来的命令行参数入口保留，不能与`--plan`混用。新协议名为paired-planned-v1，安全观测仍为paired-bundle-v2；注入参数仅供采集器/验收器读取，不投影给Agent。

加入compound场景：容量下降且入口上升。验收分别要求实际配置匹配、入口速率比≥1.5、参考健康、事件发送前症状与业务退化；不能仅凭场景名称判定采集成功。每份有效快照继续派生trace_only、runtime_only，两者不计作新的独立故障样本。

## 开发集与保留集

- `evals/plans/paired-development-v1.json`：沿用已见的五类开发参数，新增compound（60ms、池3→1、10→17请求/秒），每窗口15秒、每类2次。
- `evals/plans/paired-heldout-v1.json`：采用032中的80ms参考参数，补充compound（池3→1、8→13请求/秒），每窗口20秒、每类2次。两文件的完整参数对不重合，单个参数可以重合。
- **本轮保留集只固定参数，不采集、不运行策略、不查看结果。** 参数计划固定不等于样本或评测协议已经冻结。待机制、提示、预算和评分规则固定后再采集；先按预设门槛验收数据质量，保留全部失败，再作最终对照。不能看到结果后删样本或调整阈值仍称独立测试。
- 开发回放入口拒绝heldout标签，这是流程保护，不是访问安全隔离。CLI等底层接口仍可读取本地文件，开发者须遵守实验纪律。

```powershell
python -m evals.collect_paired_windows collect .snapshots/NEW_DEV_RUN --plan evals/plans/paired-development-v1.json
python -m evals.collect_paired_windows audit .snapshots/NEW_DEV_RUN
python -m evals.replay_paired_fixed .snapshots/NEW_DEV_RUN --output .snapshots/NEW_REPLAY.private.json
python -m unittest discover -s tests -p 'test_paired*.py' -v
```

运行目录不覆盖；采集失败仍写入manifest，finally恢复默认配置并作独立业务验收。audit成功只代表可重建与完整性一致；其中可能仍有采集失败或任务不准入，须分别报告。

## 本轮验证

本轮实测已完成：`.snapshots/paired-20261109-development-v1`记录六类场景各两次，12/12采集有效且任务准入通过；5220次计入窗口的请求（不含预热/恢复），原始观测离线重建、两种来源消融溯源及默认配置/业务恢复均通过。复合场景两次入口速率比为1.69995/1.70056，实际池容量3→1。本轮没有采集失败，不由此推断长期稳定性。

固定规则回放见`.snapshots/paired-20261109-fixed.private.json`：12份完整证据的类别均符合场景预期（含2份competing_changes）；trace_only对稳定/重启/下游6份仍可给出对应观测解释，对容量/入口/复合6份保留pre_send并拒答变化原因；runtime_only共12份均拒答且stage=unknown。36份报告全部completed。来源派生不是独立样本，这些只是开发集类别/拒答检查，未评测逐主张语义准确率，也没有模型比较或泛化结论。

验证：337项全量测试通过（159.008秒，含PostgreSQL回归），新增4项计划测试覆盖参数机制约束、开发/保留集不重合、失败保留、输入计划篡改与heldout回放拒绝；CLI帮助和本轮差异检查通过。模型调用0。预先固定的保留集仍未采集。

## 后续主线与未实现部分

下一步立即进入细粒度只读工具与主动调查状态：先做窗口摘要、请求下钻、配置比较和入口比较四类动作；用有限条件表达证据缺口、候选查询与预期结果。配置查询不能独自断言入口稳定，容量与入口假设允许同时成立。

停止条件区分充分证据、可继续判别、预算不足与来源缺失。随后比较同预算规则、ReAct、主动调查，并消融查询规划和查询评分。引用存在不等于主张受支持，语义质量须单独审查。

部分证据冲突暂不混入真实故障集：采集层已有Trace/Runtime配置不一致拒收；未来人为构造的矛盾须单列合成鲁棒性集，不能当作真实故障或独立泛化成绩。当前也未新增细粒度工具、查询价值评分或语义验证器。
