# 只读证据工具与固定流程基线

## 当前范围

这是规则基线，不是 LLM Agent。输入仅为一个 Trace ID，输出为带证据引用的结构化 JSON。后续 Agent 可复用观测接口，但不能把基线规则的输出冒充模型自主诊断结果。

调查模块位于 `backend/investigation/`，不导入 `lab`、`evals` 或读取实验结果。`evals/run_baseline.py` 拥有故障控制与真值，通过独立进程调用调查入口，只传 Trace ID。

## 四个工具

| 工具 | 数据来源 | 限制 |
| --- | --- | --- |
| get_trace | 本机 Jaeger API | Trace ID 必须为 32 位小写十六进制；最多 1 MB 响应、50 个 span、32 KB 投影；不跟随重定向 |
| get_service_topology | 版本化实验服务契约 lab-contract:v1 | 固定 orders → inventory:8001，不读取包含故障开关的 Compose 全配置 |
| get_runtime_config | 订单容器内 INVENTORY_BASE_URL | 固定读取这一项，只返回 scheme/host/port；不返回密码、路径、查询串 |
| probe_inventory | 订单容器内 GET 正确库存地址 | 只探测固定 demo 商品；不会改变业务状态，但会产生新的观测流量 |

运行配置与探针使用 Docker 的固定命令适配器，无任意 Shell、URL 或文件参数。调用 HTTP 设置 3 秒网络超时，读取过程中检查 5 秒预算；Docker 命令超时为 10 秒。工具失败返回结构化 error_code，不把异常原文或密钥带入报告。span 只保留白名单字段，不输出堆栈、任意标签和 Resource 环境信息。

这是代码/API 层面的边界，不是操作系统沙箱。进程仍使用宿主机 Docker 权限；未来接入模型时只开放工具方法，不能同时开放任意 exec 或文件读取能力。

## 证据与判断

每条证据包含唯一 ID、工具名、来源、查询参数、观察时间、状态和投影结果。链路内部保留 start_us 与 duration_ms 表示原始观察窗口。结论的 evidence_ids 引用本次报告中的证据，失败的工具结果也保留。

固定流程最多调用四个工具，无重复查询、重试或跨调查缓存：

1. 查询链路并检查结构。缺失、超限或不支持的结构返回 insufficient_evidence。
2. 完整成功请求低于 300 ms，返回 no_anomaly_observed，只说明这个请求没有越过阈值。
3. 完整成功请求中库存耗时至少 300 ms 且占订单耗时至少 70%，返回 inventory_latency。这是耗时环节定位，不解释内部根因。
4. 503 且下游 CLIENT span 标记错误，才检查配置。请求必须在最近 120 秒内，避免用当前配置反推历史。
5. 请求实际目标与当前配置一致、但与服务契约不同，且正确地址的独立探针成功，返回 endpoint_mismatch。
6. 其余情况返回 insufficient_evidence，不把“缺少库存 span”直接判为宕机或配置错误。

阈值为教学规则，尚未校准为生产 SLO。当前与历史数据仍有短时间变更竞争，报告明确说明这一限制。服务契约需要随合法架构变更一起维护；基线目前只支持这条双服务链路。

## 验收

本地测试覆盖健康/延迟、目标差异、探针失败、配置变更、旧/部分/缺失链路、无效输入、敏感字段过滤与源错误。

独立容器评测包含健康、延迟、端口错误、库存停止、恢复。库存停止时，固定流程缺少足够证据区分网络与服务状态，预期结果就是拒答。五个验收案例不是五种故障类别，也不构成泛化准确率评测。
