# 最小调查执行循环

## 范围

`backend/investigation/agent.py` 实现模型无关的执行器，复用四个 EvidenceTools。固定流程仍保留为对照。最初阶段使用脚本化模型替身验收执行器；后续已新增 [DeepSeek 适配器](004-deepseek-adapter.md)，真实模型准确率评测仍未完成。

模型适配器实现 `decide(context) -> dict`。context 包含当前 Trace ID、已收集证据的深拷贝和剩余工具次数。动作 JSON Schema 可从 `ACTION.json_schema()` 获取。

工具动作示例：`{"kind": "tool", "tool": "get_trace"}`。四个工具均无模型提供的参数；get_trace 绑定调查入口的 Trace ID，其余目标沿用现有固定适配器。未知工具与多余字段直接终止调查，不采用动态属性查找或任意命令执行。

结束动作包含 `kind: finish` 和 `finding`，后者沿用 code、summary、evidence_ids、limitations。报告 strategy 为 `bounded_agent_v1`，以区别于规则基线。

## 预算与失败

工具调用默认最多 6 次，可配置为 0–100；失败观测也计数。模型最多调用 N+1 次，最后一轮允许提交结论，但不能再查询工具。模型异常、无效动作或超预算均返回 insufficient_evidence，保留已有证据，不回显异常原文。

这只是调用次数限制，不是总耗时或 token 预算。同步模型适配器必须自行设置网络超时；当前不能中断一个阻塞的模型调用。工具继续使用其现有超时。本阶段不做重复查询缓存、自动重试、持久化、取消或假设状态管理。

## 证据边界

结论引用必须属于本次调查且不能重复。确定性结论必须引用至少一条成功观测；证据不足允许没有引用。模型收到深拷贝，不能通过修改上下文篡改执行器保存的证据。

这些校验只保证引用完整性，不保证证据实际支持结论；例如一条成功的拓扑查询仍不足以证明库存延迟。诊断语义需要后续独立场景评测，不能用执行器测试替代。模型适配器仍是进程内可信代码，这不是操作系统沙箱。

## 验收

运行 `.\.venv\Scripts\python.exe -m unittest discover -s tests -v`。

测试覆盖最后一次工具调用后正常结束、重复查询预算、未知工具和目标参数拒绝、伪造/空/重复引用、失败证据、上下文篡改隔离、模型异常脱敏、输入校验、零预算和四个工具分发。CLI 默认运行固定流程，后续新增的 `--strategy agent` 通过 DeepSeek 适配器调用本执行器。
