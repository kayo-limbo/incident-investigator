# 增强订单任务与迁移验证计划

日期：2026-11-05。状态：规划，未实现、未运行新实验。本次不引入依赖或复制外部源码。

2026-11-05 实现跟进：下述最小里程碑已有独立实验协议、四组真实采集及两份缺失条件、三策略回放和本地测试；两轮24次真实模型调查完成且离线重算一致。方案细节与未完成边界见 [028](028-frozen-evidence-bundles.md)，效果以 [实验记录](../experiments/bundle-comparison.md) 为准。以下保留原始规划，不将计划能力视为已实现。

## 目标与依据

项目以 Agent 调查机制为主，保留既有任务、预算、取消和恢复能力作为支撑。继续使用订单环境，逐项验证主动调查、结论证据验证与多 Agent 协作；随后冻结策略做第二套拓扑迁移。工作台、审批处置与额外平台建设后置。

当前 [窗口摘要](../../backend/investigation/window_queries.py) 已暴露库存耗时、发送前耗时和池超时；[规则基线](../../backend/investigation/window_baseline.py) 通常先分类再下钻举证。[假设动作](../../backend/investigation/hypothesis_agent.py) 目前只支持 get_snapshot_trace，purpose 为文本。因此现有任务适合作为回归，尚不足以检验跨来源的查询决策。已有五场景成绩不能证明泛化；库存慢与池竞争并存也不自动证明两个独立根因。

## 下一次实现：一个最小里程碑

交付一组“订单变慢、不同解释”的真实环境任务，以及 Trace 加一种必要证据来源的冻结回放。先复用现有下游延迟和连接池实验，不新增业务服务。缺失证据作为观测条件单独计数，不算新增故障机制。

| 变体 | 调查问题 | 验收与限制 |
| --- | --- | --- |
| 下游慢 | 慢发生在库存处理还是调用方等待？ | 独立请求与 span 观测确认实际延迟；不向调查侧暴露延迟注入开关 |
| 调用方等待 | 下游正常时，等待是否随并发与池容量变化？ | 对照低负载/足量连接；发送前耗时只能直接支持等待现象，单独不足以证明纯池等待 |
| 关键证据缺失 | 同类告警能支持多精细的结论？ | 有意控制证据可见性并记录覆盖状态；允许定位异常阶段但拒绝具体原因，不能把所有拒答都判正确 |

首选新增来源为有时间范围的实际客户端配置与负载观测，只暴露现实诊断可获取的值；采集时生成并冻结，不能从评测计划推导“观测”。若现有指标不能区分候选解释，先补必要观测并修订协议，再采集正式样本。初始输入采用症状告警，详细信息通过相同工具向所有策略开放；不刻意削弱规则或隐藏其本可查询的数据。

拟按以下范围实现，实际新文件名在编码时确定：

| 范围 | 最小修改 |
| --- | --- |
| lab/orders 与实验采集脚本 | 采集实际负载、客户端配置及时间范围；保留注入、独立业务检查和恢复职责 |
| backend/investigation/evidence_models.py、snapshot_store.py、window_queries.py | 新版本证据包：来源、时间范围、覆盖状态、字段引用与内容标识；保留旧快照读取路径 |
| window_investigation.py、hypothesis_agent.py 及对应动作校验/模型适配 | 开放必要只读查询并计入共享预算；不在此轮加入新的规划算法或多 Agent |
| window_baseline.py 与新评测入口 | 公平适配三策略；旧基线与历史协议保留，新协议独立命名 |
| tests 与 docs/experiments | 覆盖真值隔离、跨包引用、数据缺失、预算及可重复回放，保存失败与独立验收记录 |

验收门槛：

1. 三个变体均保存独立业务观测，注入退出后确认恢复；未实际出现预期现象的采集判无效并保留记录。
2. 人工能指出至少两个候选解释及可区分它们的查询；缺失变体明确哪些结论无法从可见证据识别。
3. 所有来源冻结在同一证据包并记录各自时间范围，回放不读取实时配置；工具结果不包含场景标签、答案或注入控制信息。
4. 规则、普通 ReAct、现有假设策略使用相同证据权限和工具预算完成回放，执行失败与诊断错误分开统计。真实模型结果与替身测试分开记录。
5. 先完成协议/工具离线检查与真实环境采集，再按预先固定的模型配置、预算和重复次数运行模型对照。无需 Agent 超过规则才算完成本里程碑。

## 后续三个机制的实验

每次只加入一个可归因的改动，保留此前策略。主动调查比较固定查询顺序、普通 ReAct、现有假设策略和判别性查询，记录正确率、正确调查所需查询数、重复/无效查询及全部失败成本。无效查询的判定标准在评测前固定，不能只依赖模型自述。

证据验证区分观测与因果主张，先检查可确定的数值/范围/引用，再按需要加入模型审查。报告错误结论拦截率与正确结论误拒率，明确分母；补查、拒答与额外调用均计入原预算。验证器可参与调查，但最终评分依赖独立真值与人工核验标准，不能由同一验证器自评效果。

多 Agent 首版最多两个竞争假设分支，返回结构化支持、反证、未知项与消耗。父子共享预算，去重包含快照和参数范围；冲突通过证据补查处理。比较单 Agent、顺序委派与并行委派，补充共享证据/不共享、协调补查/直接汇总的消融。分别报告同总预算和等延迟条件下的质量，不能把增加总消耗当成协作增益。累计 token 阈值仍是响应后检查，不承诺费用硬上限。

## 数据划分与第二套拓扑

订单环境依次覆盖参数变化、故障位置与干扰、组合与证据缺失。采集前固定场景族、参数范围、样本划分、重复次数、预算与评分规则。同一环境快照的模型重复回放不算独立环境样本；用于修改提示或策略的样本转为开发集。旧任务作为回归集，不因参数更换就宣称未知故障泛化。

三个机制分别完成首轮对照、协议稳定后进入迁移，无需等待全部正收益。候选第二环境为“任务提交 → Worker → 外部处理服务”，使提交成功与处理完成分离，检验排队、执行、下游耗时的区分；最终拓扑在该阶段根据覆盖缺口选择，不建设完整新业务系统，也不只改服务名称。

迁移前冻结策略代码、提示、模型配置、预算、评分规则与证据接口版本。允许适配数据采集、拓扑描述、正常服务契约与必要工具映射；适配器不得编码根因判定或按答案预聚合证据。记录所有修改，优先由调查核心处理通用服务、调用边和阶段，环境适配器处理业务字段。结论分为异常定位与原因主张，避免把 inventory 固化为通用类别。

| 实验 | 允许变化 | 结果口径 |
| --- | --- | --- |
| 无策略调优迁移 | 上述环境适配，不改调查/验证/协调策略及提示决策逻辑 | 同一机制在另一拓扑的表现；失败照实保留 |
| 有限适配 | 使用独立开发样本调整提示或规则，登记改动与成本，再测未用样本 | 经适配后的效果，不能覆盖首次迁移成绩 |

若查看第二环境测试结果后调优，该测试集不再支持新的未调优结论。报告质量、拒答、查询/token/耗时、各机制相对基线变化、适配模块与成本。第二拓扑迁移和未知故障机制泛化分别报告，前者不能替代后者。
