# 同工具、同停止协议的查询策略适配

2026-11-11：新增`active_policies.py`与`active_cli.py`，复用034的ActiveInvestigation和现有HTTPX模型传输。未引入新框架或复制外部代码。**本协议比较查询选择，诊断和停止仍由共同确定性规则生成；不是模型独立诊断准确率实验。**

## 三种策略

| 策略 | 决策输入与动作 | 共同边界 |
| --- | --- | --- |
| fixed | 固定顺序：参考摘要、事件摘要、配置比较、入口比较 | 同一工具、证据与自动停止规则；健康或来源缺失可提前停 |
| react | 已观测证据、工具预算、工具结果枚举；输出Query | 不给假设状态或评分候选，允许已发现请求下钻 |
| active | 同上，加程序假设状态及候选建议；输出Plan | 校验假设ID、gap、预期分支；评分仅建议，不强制最高分 |

普通策略由执行器补足兼容Plan，报告标记`plan_origin=executor_from_query`，不冒充模型规划。主动策略记录model来源，固定策略记录fixed_policy。所有结论来自共同状态机，不把模型查询动作当作诊断成功。

`--no-scoring`仅用于active：移除分数并恢复固定候选顺序，保留假设、候选及计划校验。这是“分数展示与排序”的有限消融，不是完全移除主动规划；完整的去规划消融尚未实现。固定流程不主动下钻单请求，其他两种有相同工具权限可选择下钻。

## 预算与失败

默认含告警6次工具预算，最多5次模型决策（budget−1），120秒总期限和40000累计token停止阈值。调用账本保留模型失败/超时/取消及未知用量；响应后检查token，达到阈值或用量未知时不执行候选动作。最后一次响应可能超额，不是费用硬上限。

非法Schema、预期分支、重复查询等直接结束，不自动重试；动作不进入已接纳调查历史。模型错误保留已有白名单原因码，不保存供应商原文。报告分别记录执行termination与领域state.stop，执行completed可能对应证据不足，不等于诊断正确。

库层取消抛出携带部分报告的PolicyCancelled；CLI保存部分报告并返回130。模型传输使用async with关闭资源。无Worker持久化恢复、纠错或并行执行；快照读取失败仍由调用方处理，CLI可能留下空目标文件，重试需新路径。

## 使用

默认fixed不读取密钥、不访问模型。输出独占创建，不覆盖已有报告：

```powershell
python -m backend.investigation.active_cli SNAPSHOT_SHA256 --store .snapshots/paired-20261109-development-v1/snapshots --output .snapshots/NEW_POLICY.private.json
python -m unittest discover -s tests -p 'test_active_policies.py' -v
```

显式`--strategy react`或`active`才读取既有ModelConfig配置并调用API，会外发受限观测并产生费用；本轮没有执行。单快照CLI不判定数据集split，保留集纪律需由后续冻结批量评测入口保证，不把本地文件接口宣称为隔离边界。
