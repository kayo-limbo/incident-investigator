# 调查恢复与租约一致性

日期：2026-10-30。范围：Worker 的 hypotheses 策略；独立调查 CLI 不启用持久化。

## 解决的问题

任务队列恢复的是执行资格，图检查点恢复的是调查进度。两者不能独立判定写权限：旧 Worker 即使已经失去租约，也可能仍在等待模型结果。本实现让检查点读写与任务所有权校验共用 PostgreSQL 事务和任务行锁，事务结束前再次检查数据库时钟下的有效租约。

`task_id` 同时作为 LangGraph `thread_id`，跨 Worker 接管保持不变；`run_token` 每次领取更新，只作为当前执行权凭证。图运行记录绑定请求摘要和协议 `hypotheses-graph-v1`，不匹配则拒绝恢复。最新检查点按数据库分配的位置排序，不依赖不同 Worker 的本机时钟。串行图通过任务行锁串行写入。

## 实现与恢复语义

LangGraph 1.2.18、langgraph-checkpoint 4.3.1 提供图调度、检查点格式和同步持久化边界。本项目实现 `LeaseCheckpointSaver`，复用现有 psycopg 连接事务，将租约隔离和业务恢复策略加入持久化边界；没有复制第三方实现代码，也没有采用独立事务的通用 PostgresSaver。

图使用 `durability="sync"`，持久化完整步骤后才进入下一步骤。保存证据、假设历史、查询记录、模型动作、用量及报告，恢复后继续原图位置。调用次数、工具预算和已知 token 统计从已提交状态累计；首次开始时记录数据库绝对截止时间，恢复时换算成本次单调时钟预算，停机也消耗时限。报告中的本次运行 elapsed 时间不等同于跨重启总墙钟时间。

模型调用之前先持久化 `inflight_turn`。模型结果和用量提交检查点时，在同一事务清除此标记。若进程退出后标记仍存在，可能请求尚未发出，也可能已收费但结果丢失；恢复时返回 `usage_unavailable`，不自动重发。这是保守停止策略，不是模型请求 exactly-once，也没有猜测丢失的 token 数量。

| 中断位置 | 接管行为 |
| --- | --- |
| 已提交模型决策、尚未执行工具 | 从后续节点继续，不重发已提交决策 |
| 模型调用尚未可靠提交 | 停止自动调用，报告未知用量 |
| 工具执行后、检查点提交前 | 可重新执行只读冻结快照工具 |
| 最终报告检查点已提交、任务终态尚未提交 | 补写任务终态，不再调用模型 |
| 截止时间已过、尚无最终报告 | 保留已提交证据并返回超时 |
| 旧 Worker 尝试写入 | 所有权校验失败，事务回滚 |

检查点事务与任务最终状态事务并未合并；终态补交负责跨越这一间隙。外部请求与数据库也不能原子提交。数据库失败向 Worker 传播，后续由租约和恢复流程裁决，而不是直接重试模型节点。

## 适用边界

此适配器仅支持当前串行图的完整 super-step 检查点，不持久化 pending writes，不支持并行分支、子图、历史回放或人工编辑状态。下一阶段若加入 multi-agent，必须重新设计分支写入、合并和预算，不能复用当前限制并声称完整支持。

检查点是内部受信任数据，没有外部任意恢复接口；包含原始模型动作和观测证据，不含模型客户端或密钥。尚未实现检查点保留期限及清理策略，不适合无限期运行。快照必须仍可读取，当前不提供跨主机快照复制。没有处置副作用和审批，未来加入时仍需独立幂等键及业务验收。

## 升级与验证

停止 API 和全部 Worker，在设置现有 `TASK_DATABASE_URL` 后执行：

```powershell
.\.venv\Scripts\python.exe -m backend.tasks init
```

schema 4 新增 `task_graph_runs` 与 `task_graph_checkpoints`。旧任务不会凭空产生历史检查点，首次按新实现执行时开始记录。测试使用随机 schema 并清理，不自动迁移本机默认业务 schema。

设置专用测试库 `TASK_TEST_DATABASE_URL` 后执行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_graph_recovery.py
```

测试启动真实子进程并通过 `os._exit` 中止，使用真实 PostgreSQL 与替身模型，验证步骤恢复、未知调用停止、跨尝试 token 预算、终态补交、截止时间与所有权隔离。测试通过 SQL 提前过期租约，不代表测量了真实等待租约到期的接管耗时；没有真实模型诊断效果或性能提升结论。

最终验证：全量 219 项测试通过，无跳过，其中新增 8 项恢复测试；`pip check` 无依赖冲突。回归期间修复了无检查点入口传入同步持久化参数导致的框架属性错误，并将响应流取消测试改为等待进入流后再取消，避免依赖 50 毫秒内已打开流的时序假设。

参考：[LangGraph 持久化](https://docs.langchain.com/oss/python/langgraph/persistence)、[持久执行](https://docs.langchain.com/oss/python/langgraph/durable-execution)。实际接口以锁定依赖和恢复测试为准。
