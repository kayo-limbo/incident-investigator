# 冻结窗口规则与 Agent 对照：2026-10-19

本次完成窗口调查功能验收。四组真实负载各 24 个请求和一次预热，共 100 个请求，采集四份快照；每组规则与 Agent 使用同一快照、摘要/索引、公开阈值及最多六次工具调用。模型为配置的 `deepseek-flash`，非思考模式；没有把场景名称、期望类别或注入参数传入策略。

独立规则运行四组通过。随后真实模型对照及两轮冻结回放均保留记录，未覆盖首次失败数据。公开摘要见 [window-comparison-results.json](window-comparison-results.json)；完整原始报告为本地忽略的 `window-comparison.private.json`、`window-comparison-replay.private.json`、`window-comparison-final.private.json`。

## 失败与接口修正

| 轮次 | 规则 | Agent | 观察与修改 |
| --- | --- | --- | --- |
| 首次真实环境 | 4/4 | 3/4 | 正常场景未下钻就结束，被引用校验拒绝；其余三组通过 |
| 明确正常结论也需引用后回放 | 4/4 | 2/4 | 正常与慢下游通过；其余两组省略标签路径的 tags. 前缀，引用被拒绝 |
| 显式字段路径后回放 | 4/4 | 4/4 | 下钻 span 列出 reference_fields，Schema 约束标签路径前缀，四组通过 |

首次失败时执行器未保存被拒绝的候选正文，只能确认没有下钻且结论不满足引用校验；后续加入 `rejected_finding`，把候选与接受的结论分开保存。第二轮可直接检查到 `client.pre_send_ms` 等无效路径。没有通过放宽引用检查或把失败计为合理拒答来提高通过率。

这里使用的是开发时反复检查的同四份快照，不能把最后 4/4 写成独立测试集准确率，或证明改动收益已具有统计显著性。模型选择样本和生成结果仍有波动，后续需要更多场景、重复运行与独立测试集。

## 最后一轮结果与成本

| 场景 | 两种策略的分类 | 规则工具次数 | Agent 工具/模型次数 | Agent tokens | Agent 耗时 |
| --- | --- | ---: | ---: | ---: | ---: |

| 正常下游、小池排队 | pre_send_delay | 3 | 3 / 3 | 16,143 | 6.53 s |
| 慢下游、宽池 | inventory_latency | 3 | 5 / 5 | 29,418 | 7.75 s |
| 慢下游叠加池超时 | inventory_latency_with_pool_contention | 4 | 5 / 5 | 28,820 | 9.31 s |
| 合计 | — | 13 | 18 / 18 | 104,647 | 32.89 s |

工具次数包含每个调查的一次摘要读取，原始数据采集单列而不重复归入两种策略。tokens 是供应商返回的累计输入+输出用量，全部已知；不是价格或费用估算。规则不调用模型，token 为 0。短暂本地读取的单调时钟测量可能为 0 ms，不能据此断言无成本或给出性能倍数。

固定负载：并发 8，池超时 250 ms；正常库存处理 80 ms、慢库存 500 ms；池上限分别为 8、1、8、4。故障真值只在验证器中使用。最后一组独立 HTTP 结果确有失败，工具观测到 PoolTimeout；成功请求低发送前耗时不能掩盖失败。

最后一轮模型摘要与引用已抽查：结论描述已采集样本、能区分发送前耗时与库存耗时，并保留配置与唯一根因限制。但联合场景仍出现“慢库存导致后续连接池等待超时”一类因果化表述；现有数据直接证明的是共同出现，尚不能证明唯一因果链。这是语义层尚未解决的问题，不应被分类通过率掩盖。程序只检查引用存在、范围与协议，仍不自动证明每一句因果判断。当前规则在这四个已知观测模式上更省调用，尚无 Agent 优于规则的证据。

## 工程与恢复验收

70 项本地测试通过，其中新增 15 项覆盖四种规则模式、缺失/部分数据拒答、越界工具与快照、已读字段引用、预算、上下文隔离、截断与失败用量、CLI、评分器及离线回放不操作容器。

真实实验结束后恢复零延迟、正确库存地址、池上限 100、池等待 2000 ms，独立订单业务请求返回正常内容。两轮回放只读已冻结输入，不修改容器，不声称回放本身进行了恢复验收。

复现方法见 [窗口调查协议](../decisions/007-window-investigation.md)。本轮未实现假设版本、并发调度、累计 token/时间预算或持久化 Worker。
