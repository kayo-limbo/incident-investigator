# 模型调查独立验收

`evals.run_baseline` 支持 `--strategy baseline|agent`，共用健康、500 ms 库存延迟、错误库存端口、库存停止和恢复五个案例。评测器持有场景标签和预期结果，调查子进程只接收 Trace ID、策略和调用次数上限；删除继承环境中的两个注入参数。此边界仍不是进程权限沙箱。

每个场景记录类别是否符合预期、端到端调查耗时、工具调用次数和完整调查报告。`termination=completed` 表示正常生成报告；其余终止类型不能得分，即使 finding.code 恰好是 insufficient_evidence。评分还要求引用存在且唯一，并至少引用一条成功的链路证据。它只能检查类别与引用完整性，不能自动证明自然语言结论的每个断言都正确。

模型配置在修改容器前校验。诊断错误记录失败后继续案例；子进程超时或退出失败保存固定错误类型并中止后续案例。finally 恢复正确地址与零延迟，并通过订单业务探针确认恢复。模型子进程总等待上限 300 秒；超时中断不意味着服务商已停止计费。

命令：

```powershell
.\.venv\Scripts\python.exe -m evals.run_baseline --strategy baseline --output docs/experiments/baseline-validation.private.json
.\.venv\Scripts\python.exe -m evals.run_baseline --strategy agent
```

结果默认分开存放，模型报告采用 private.json，避免意外公开观测和生成内容。两次运行遵循相同场景定义，但各自产生请求，不能称为完全相同快照或统计意义上的受控对照。模型与规则的对比还需统一诊断标准、重复运行及人工核对。

2026-10-17 验证：当前 41 项本地测试通过；扩展后的固定流程及真实 DeepSeek 模型均在真实容器中完成五个案例，全部通过且业务恢复验证成功。原始报告分别为本地 baseline-validation.private.json 和 agent-results.private.json，均不提交 Git。

## 首次真实模型验收

开始时间：2026-10-17 17:07:25（Asia/Shanghai）。模型为 deepseek-flash（官方 API 对应 V4.1 Flash），非思考模式，单次输出上限 2048 tokens、工具上限 6 次。用户明确授权向 DeepSeek 发送实验观测数据后执行。没有向模型传递场景名称或预期答案。

| 场景 | 模型结论 | 结果 | 模型调查耗时（秒） | 模型工具次数 | 规则耗时（秒） | 规则工具次数 |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| 健康 | no_anomaly_observed | 通过 | 7.936 | 4 | 0.959 | 1 |
| 库存延迟 | inventory_latency | 通过 | 9.024 | 5 | 0.979 | 1 |
| 错误端口 | endpoint_mismatch | 通过 | 9.447 | 5 | 2.183 | 4 |
| 库存停止 | insufficient_evidence | 通过 | 12.141 | 5 | 1.343 | 3 |
| 恢复 | no_anomaly_observed | 通过 | 7.287 | 4 | 0.988 | 1 |

耗时为调查子进程的端到端墙钟时间，包含进程启动、工具和模型调用，不含场景注入与等待链路入库。两个策略分开运行，每个场景各一条请求，不能据此推导稳定性能差异。模型总计 23 次工具查询，规则总计 10 次；token 与费用尚未采集。

检查生成报告发现：延迟场景定位到库存内部耗时并承认内部根因未知；错误端口场景引用了实际请求目标、服务契约、运行配置和成功探针；库存停止场景描述连接超时且正常拒答，termination=completed，没有将探针执行错误或缺少 span 直接判为宕机。

模型在延迟、错误端口、库存停止三个场景中重复调用 get_trace；同一 Trace ID 的再次查询没有提供新的独立证据，错误端口报告也承认这是重复观测。健康与恢复场景均查询了四个工具，而规则只查询链路。下一步优先验证不可变链路快照去重与提前结束策略，保留动态配置和探针的时效性；优化收益必须重新对照验证。

五项类别符合预期只构成功能验收，未进行独立测试集、重复试验或统计准确率评估，也未逐条自动证明自然语言报告的全部断言。
