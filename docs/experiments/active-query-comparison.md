## 2026-11-18 双分支准入：单 Agent 是否漏报并存因素

**决定：暂缓双分支实验。** 在三次不同的联合故障采集中，普通 ReAct 有 13 次历史调查。12 次交付了自然摘要，逐份均明确写出库存服务端耗时升高和连接池超时，1 次因引用校验失败只交付失败提示。对读者而言，两项都读到的是 12/13；对“证据齐全且写成报告，却遗漏其中一项”这个准入问题，观察到 0/12。三次采集来自同一拓扑、同类机制，重复报告共享证据。

**核对方法。** 取历史窗口三轮、假设对照 r1–r4、既有验收 trial-1/2、纠错 r2 两轮两种纠错额度中的全部联合故障记录，按 snapshot_id 合并采集。对原始 span 按 trace 对齐订单响应、库存服务端耗时和客户端错误；三窗的成功请求均有库存 span，按最近秩重算的 P95 均超过历史协议的 250 ms，503 请求均有客户端 PoolTimeout。逐份检查已取得的 evidence：23/23 的首个成功 get_snapshot_summary 同时列出相符的库存 P95 和超时计数。此处证据在初始摘要已齐备，不能据此评价需要主动查询才能发现第二因素的任务。

**正文判读。** 逐份人工核读最终 finding.summary，只按其是否明确报告两项观测计数；分类码、被拒草稿或假设历史不能代替正文。假设策略另有 3 次 invalid_action、1 次 model_error、1 次 invalid_finding；普通 ReAct 的 1 次 invalid_finding 为窗口回放的 invalid_reference。两种单 Agent 的 17 份有效正文都写出了两个因素。本轮只核对因素是否出现，未逐句评价因果解释。例如 f620eee0 两轮 ReAct 均进一步写出库存慢导致池超时；观测直接支持成功请求库存慢与其他请求池超时共现，未识别两者的因果关系。

本地可用 `python -X utf8 .snapshots/factor-audit-20261118/audit.py` 列出按文件、策略、快照对应的原观测、首个摘要、终止原因和最终正文。仅重读冻结材料，无新增模型调用、调查工具调用或采集。当前 active 由共享规则生成诊断，未用其输出替代自然正文；本次历史样本也不代表所有强单 Agent。

### 方法与结果

### 为什么此前没有收益

1. **成功证据集基本固定。** 单一异常需两摘要与两比较，原compound也需这四项才能看到容量及入口并存；现有真实样本没有“下游变化+另一种变化”的提前分类机会。正常及来源缺失的早停已经由fixed共享。
2. **mixed下钻增加了报告要求。** 目标请求阶段有真实观测价值，但不改变窗口downstream_change所需证据；本批固定和模型都必须多查一次。去掉该要求会同时减少两者成本，不能构成主动策略优势。其余请求下钻不能消除目标定位缺口。
3. **评分实际退化为常量。** 对2,042个可继续状态检查候选，分数全部为1，评分与去评分的候选顺序零差异。当前公式统计查询覆盖的假设缺口，每个基础查询只对应一个假设需求，局部查询只对应一个定位需求；没有结果概率或查询区分度。因此本批active/no_scoring主要差别只剩是否展示常量分数，不能解释为有效信息增益消融。
4. **预期结果不是预测。** Plan要求完整复制工具结果枚举，程序负责更新与停止。已有工程约束成立，但不等于模型自主维护竞争假设、估计查询价值或决定充分性。
